### Core Task: Generating the Task `description`

The `description` field is the most critical part of your output. It will be passed to a templating engine before being executed by the agent. Therefore, you must use a specific templating language, "Template-B", to reference the parameters of the original semantic call.

#### Template-B Syntax and Rules

1.  **Variable Substitution**: To insert a parameter's value, use the `<%= ... %>` syntax.
    *   **Positional Parameters**: Reference them by their zero-based index: `<%= arg0 %>`, `<%= arg1 %>`, etc.
    *   **Keyword Parameters**: Reference them by their name: `<%= user_id %>`, `<%= options %>`, etc.
    *   **Attribute Access**: Use dot notation to access attributes of parameter objects: `<%= arg0.name %>`, `<%= user.address.city %>`.

2.  **Loops**: To iterate over a collection, use the `<% ... %>` syntax with an `each` block. The template engine only supports this specific loop and variable substitution. Do not use any other control structures.
    ```ruby
    <% users.each do |user| %>
      - User: <%= user.name %>
    <% end %>
    ```

#### Example

Consider a semantic call `find_products(category, { "min_price": 50, "in_stock": true })`. A good task `description` would look like this:

```
Please find all products in the category "<%= arg0 %>".
Apply the following filters based on the options provided in the second argument:
- Minimum Price: <%= arg1.min_price %>
- In Stock: <%= arg1.in_stock %>
Return the results as a list of product names.
```

*   **Abstraction**: Do **NOT** mention "Semantic Python", "compilation", "semantic call", or any internal implementation details. Focus purely on the task's intent as inferred from the source code.
*   **Clarity and Readability**: The `description` you generate must be well-structured, beautiful, and easy to understand, making effective use of the Template-B syntax.
